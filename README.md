# ПрокатCRM — CRM для аренды строительного инструмента

Next.js 15 / React 19 / TypeScript / Tailwind CSS + **настоящий бэкенд**: SQLite-база на диске (через `better-sqlite3`), API-роуты, реальное сохранение файлов и фоновый планировщик автоматических штрафов.

## Что реально работает

### База данных
Все данные хранятся в файле `data/app.db` (SQLite) — не в localStorage браузера. Это значит:
- Данные переживают перезапуск сервера и очистку браузера
- К одной базе может обращаться несколько человек в локальной сети (см. «Доступ с других компьютеров» ниже)
- Таблицы: `clients`, `inventory_items`, `rentals`, `activity_log` (создаются автоматически при первом запуске)

### Каталог инструмента (`/catalog`)
- Список инструмента с фото, статусом (свободен / в аренде / на обслуживании / списан), категорией, филиалом
- Добавление/редактирование (`/catalog/new`, `/catalog/[id]`) — фото, артикул, серийный номер, стоимость покупки и аренды
- **QR-код** генерируется автоматически на основе артикула (виден на карточке товара)
- При оформлении аренды товар из каталога автоматически переходит в статус «В аренде», а при завершении/отмене — обратно в «Свободен»
- История аренд по каждой единице инструмента — реальная, собирается из фактических аренд

### Клиенты (`/clients`)
Как и раньше: таблица, фильтры, сортировка, импорт/экспорт CSV и Excel — теперь всё через реальную БД. Фото клиента загружается на диск по-настоящему.

### Новая аренда (`/rentals/new`)
- Добавление товара теперь имеет два режима: **«Из каталога»** (поиск среди свободного инструмента) и **«Вручную»** (для комплектов/услуг, которых пока нет в каталоге)
- Переключатель «Почасовой штраф» — при включении задаётся ставка (₸/час), и штраф начисляется автоматически (см. ниже)

### Автоматические штрафы за просрочку
Фоновый процесс (встроен в `src/lib/repo.ts`) каждый час проверяет все аренды в статусе «В аренде»/«Забронировано»:
- Если срок аренды истёк — статус меняется на «Просрочено»
- Если включён «Почасовой штраф» — за каждый полный час просрочки начисляется штраф по заданной ставке, сумма аренды растёт автоматически
- Работает, пока запущен `npm run dev` / `npm start` (первый прогон — через 10 секунд после старта, затем каждый час)
- **Важно**: если сервер не работает постоянно (закрыли терминал, выключили компьютер), проверка не идёт. Для таких случаев есть ручной эндпоинт `GET /api/cron` — можно вызвать вручную или повесить на Windows Task Scheduler / внешний cron

### Реальное сохранение файлов
Фото клиентов и инструмента загружаются через `POST /api/upload` и сохраняются на диск в `public/uploads/` — не в браузере, а по-настоящему на компьютере, где запущен сервер. Ограничение: до 8МБ, форматы png/jpg/jpeg/webp/gif/pdf.

## Технологии

Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS 4, Zustand (клиентский кэш, гидратируется с сервера при загрузке), better-sqlite3, qrcode, xlsx (SheetJS).

## Известные ограничения

- **Один компьютер = один сервер = одна база.** Чтобы несколько сотрудников работали с одними данными одновременно, нужно запустить `npm run dev`/`npm start` на одном компьютере (или сервере) в сети, а остальные — открывать его по IP-адресу в браузере (см. ниже). Полноценный облачный хостинг — следующий шаг.
- Нет авторизации/ролей — единственный «оператор» задан в `src/lib/current-user.ts`.
- «Комплекты» и «Услуги» пока добавляются вручную (свободный ввод) — в каталоге есть только физический инструмент.
- Учёт ТО и ремонта инструмента — ещё не реализован (заготовка есть на карточке товара).

## Запуск

```bash
npm install
npm run dev
```

Откройте http://localhost:3000 — при первом запуске автоматически создастся база данных `data/app.db`.

### Доступ с других компьютеров в локальной сети

`npm run dev` печатает в консоли адрес вида `http://192.168.X.X:3000` — его можно открыть с любого компьютера в той же Wi-Fi/локальной сети. Для постоянной работы лучше использовать `npm run build && npm start` вместо `dev`.

## Структура

```
data/app.db                   # SQLite база (создаётся автоматически)
public/uploads/                # загруженные фото (создаётся автоматически)
src/
  app/
    api/                       # REST API: clients, inventory, rentals, upload, cron, activity
    page.tsx                   # Главная
    rentals/, rentals/new/, rentals/[id]/
    clients/, clients/new/, clients/[id]/
    catalog/, catalog/new/, catalog/[id]/
    analytics/ finance/ ...    # остальные разделы — заглушки
  components/
    layout/store-hydrator.tsx  # загружает данные с сервера при старте приложения
    rentals/                   # карточка, фильтры, добавление позиций (каталог + вручную)
    clients/                   # форма клиента, быстрое добавление
    inventory/                 # форма инструмента, QR-код
    ui/photo-upload.tsx        # реальная загрузка фото на диск
  lib/
    db.ts                      # подключение к SQLite, создание таблиц
    repo.ts                    # вся бизнес-логика с данными + фоновый планировщик штрафов
    store.ts                   # Zustand — клиентский кэш поверх реального API
    types.ts, utils.ts, mock-data.ts, current-user.ts, client-io.ts
```

## Как перейти на «настоящий» продакшн (следующие шаги)

1. **PostgreSQL вместо SQLite** — если нужен доступ из интернета/облака (SQLite отлично работает локально на Windows, но не годится для serverless-хостинга типа Vercel).
2. **NextAuth** — вход по логину/паролю, роли (менеджер/админ/оператор филиала).
3. **Внешний cron** — если хостинг serverless, замените фоновый планировщик на вызов `GET /api/cron` через внешний сервис (напр. cron-job.org) раз в час.
4. **Комплекты и услуги в каталоге** — расширить схему `inventory_items` или завести отдельные таблицы.
