# Домен qural-saiman.kz: сайт-визитка и CRM

Цель: `qural-saiman.kz` открывает сайт-визитку, а CRM открывается по своему
адресу на этом же домене.

Сначала два факта, которые меняют план. Без них инструкция приведёт в тупик.

---

## Факт 1. Railway не умеет делить один домен по путям

В Railway **один домен ведёт ровно на один сервис**, маршрутизации по пути
(`/crm` → один сервис, `/` → другой) у платформы нет
([документация Railway](https://docs.railway.com/networking/domains/working-with-domains)).

Поэтому есть два пути:

| | Вариант А: поддомен | Вариант Б: путь `/crm` |
|---|---|---|
| Адрес CRM | `crm.qural-saiman.kz` | `qural-saiman.kz/crm` |
| Изменения в коде CRM | не нужны | нужны: CRM переводится на базовый путь `/crm` (около 80 запросов к API в 32 файлах, ссылки, редиректы входа, ссылки на документы) |
| Лишние сервисы | нет | нужен отдельный сервис-прокси (Caddy) перед сайтом и CRM |
| Цена в Railway | как сейчас | +1 постоянно работающий сервис |
| Что сломается, если прокси упадёт | ничего | и сайт, и CRM одновременно |
| Вход в CRM | отдельный от сайта (своя cookie) | cookie общая с сайтом |

**Рекомендация — вариант А.** Так делают почти все: `crm.`, `app.`,
`lk.` — это стандарт. Ничего не нужно переписывать, сайт и CRM не зависят
друг от друга, а сбой сайта-визитки не кладёт рабочую систему. Вариант Б
описан ниже полностью — если адрес именно `/crm` принципиален, скажите, и я
переведу CRM на базовый путь.

---

## Факт 2. Домен .kz и серверы за границей

Правила зоны .kz, по которым работают казахстанские регистраторы, называют
**размещение ресурсов домена за пределами Казахстана основанием для
приостановления домена**: регистратура приостанавливает делегирование, на
исправление дают 10 рабочих дней
([правила регистратора PS.kz](https://docs.ps.kz/legal-docs/contracts/rules-domain-names-kz),
[обзор требований Рег.ру](https://help.reg.ru/support/domains/spravka-po-domennym-zonam/domennaya-zona-kz),
[Hostland](https://www.hostland.ru/ru/docs/services/pravila-registratsii-domenov-kz)).
При регистрации домена в анкете указывается IP и адрес сервера, где лежит
сайт.

Серверы Railway находятся в США, Европе и Сингапуре — в Казахстане их нет.
На практике многие .kz-сайты живут за границей и проверок не замечают, но это
риск, и о нём надо знать заранее, а не когда домен уже выключили.

Как снять риск (от простого к надёжному):

1. **Сайт-визитку разместить на казахстанском хостинге** (PS.kz, Hoster.kz и
   т. п. — статический сайт стоит копейки). Тогда основной адрес
   `qural-saiman.kz` законно живёт в Казахстане. CRM — внутренний инструмент,
   её видят только сотрудники.
2. **CRM держать на поддомене и на Railway** — это остаточный риск: поддомен
   тоже ресурс домена .kz. Если хочется нулевого риска — CRM оставить на
   адресе Railway (`…up.railway.app`) или на отдельном домене не в зоне .kz
   (например `qural-saiman.com`), а на сайте поставить кнопку «Вход для
   сотрудников».
3. **Перенести CRM на сервер в Казахстане** (VPS у казахстанского хостера).
   Это полный переезд с Railway — отдельная работа, если понадобится.

Уточните у своего регистратора, как они применяют это правило: он же будет
присылать уведомление, если что.

## Вариант А: сайт на `qural-saiman.kz`, CRM на `crm.qural-saiman.kz`

### Что понадобится

- доступ к панели регистратора, где куплен `qural-saiman.kz` (раздел DNS);
- доступ к проекту в Railway;
- 15 минут работы и до суток ожидания, пока DNS разойдётся по миру.

### Шаг 1. Подключить поддомен к CRM в Railway

1. Railway → проект → сервис CRM → **Settings** → **Public Networking**.
2. **+ Custom Domain** → ввести `crm.qural-saiman.kz` → **Add Domain**.
3. Railway покажет **две записи** — их нужно внести у регистратора:
   - **CNAME**: имя `crm`, значение вида `xxxxxx.up.railway.app`;
   - **TXT**: имя вида `_railway-verify.crm`, значение — длинная строка.

   Обе обязательны: без TXT Railway не подтвердит домен и будет отвечать 404.
   Окно Railway не закрывайте — значения понадобятся на следующем шаге.

### Шаг 2. Внести записи у регистратора

1. Панель регистратора → домен `qural-saiman.kz` → **Управление DNS**
   (может называться «DNS-записи», «Зона DNS»).
2. Добавить запись **CNAME**: хост `crm`, значение — строка из Railway
   (с точкой на конце, если панель этого требует).
3. Добавить запись **TXT**: хост — как выдал Railway, значение — строка из
   Railway.
4. Сохранить. Если у `crm` уже была какая-то запись (A или CNAME) — удалить её,
   двух записей на одно имя быть не должно.

### Шаг 3. Дождаться проверки

- В Railway у домена появится зелёная галочка — обычно в течение часа,
  иногда до 72 часов.
- Сертификат HTTPS Railway выпускает сам (Let's Encrypt), примерно в течение
  часа после проверки DNS, и сам продлевает.
- Проверка: открыть `https://crm.qural-saiman.kz` — должна открыться страница
  входа CRM.

Старый адрес `rental-crm-production-da31.up.railway.app` продолжит работать —
его можно оставить как запасной.

### Шаг 4. После переезда на новый адрес

- Сотрудникам — войти заново по новому адресу: вход привязан к адресу, старая
  сессия туда не переедет.
- Ссылки на документы, отправленные клиентам раньше, **продолжат работать** по
  старому адресу. Новые ссылки система сама будет делать с новым адресом.
- Если в браузерах сохранены закладки — обновить.

### Шаг 5. Сайт-визитка на `qural-saiman.kz`

Когда сделаем сайт:

- **Если на казахстанском хостинге (рекомендуется):** у регистратора для
  корня домена (`@`) и для `www` поставить **A-запись** на IP хостинга —
  хостер его даст. Запись `crm` не трогать.
- **Если на Railway:** второй сервис в том же проекте → Custom Domain
  `qural-saiman.kz`. Для корня домена (`@`) обычный CNAME по стандарту DNS
  запрещён, поэтому нужен DNS с «CNAME flattening» или ALIAS. Большинство
  казахстанских панелей этого не умеют — тогда нужно перенести DNS домена в
  Cloudflare (бесплатно): завести домен в Cloudflare, у регистратора сменить
  NS-серверы на выданные Cloudflare, и уже там завести CNAME на корень
  ([Railway о корневых доменах](https://docs.railway.com/networking/domains/working-with-domains)).
  Если включать оранжевое облако (прокси Cloudflare) — в Cloudflare выставить
  SSL/TLS в режим **Full** (не «Flexible» и не «Full (strict)»).

## Вариант Б: CRM по адресу `qural-saiman.kz/crm`

Технически делается через отдельный сервис-прокси, который стоит на домене и
раздаёт запросы: `/crm/*` — в CRM, всё остальное — на сайт.

```
qural-saiman.kz ──► Caddy (прокси) ──► /crm/*  ──► сервис CRM   (внутренняя сеть Railway)
                                   └─► всё остальное ──► сервис сайта
```

### Что нужно сделать в коде CRM (моя часть)

1. Включить базовый путь: `basePath: "/crm"` в `next.config.ts`.
2. Поправить все обращения к API в браузере: Next сам добавляет `/crm` к
   страницам и ссылкам, но **не** к ручным запросам `fetch("/api/…")` — их в
   проекте около 80 в 32 файлах. Вынести в одну функцию, которая дописывает
   базовый путь.
3. Проверить вход и выход (редиректы на `/login`), `middleware.ts` (открытые
   пути `/login`, `/d/`, `/api/version`), ссылки на документы для клиентов
   (`/d/…` → `/crm/d/…`), загрузку файлов (`/uploads/…`).
4. Запуск CRM на внутреннем адресе: команда запуска `next start -H :: -p $PORT`
   — внутренняя сеть в старых окружениях Railway работает только по IPv6.
5. После переезда все ранее отправленные клиентам ссылки на документы
   перестанут открываться по старому адресу — их придётся отправить заново.

Это полдня работы и проверки. До решения по варианту не начинаю.

### Что нужно сделать в Railway (ваша часть)

1. **Сервис сайта.** Добавить в проект сервис с сайтом-визиткой. Публичный
   домен ему не нужен.
2. **Сервис-прокси.** Railway → проект → **+ New** → **Template** → найти
   «Caddy Reverse Proxy» ([шаблон Railway](https://github.com/railwayapp-templates/caddy-reverse-proxy/tree/main)).
   В его `Caddyfile` правила такие (имена сервисов подставить свои):

   ```
   :{$PORT} {
     handle /crm* {
       reverse_proxy {$CRM_HOST}:{$CRM_PORT}
     }
     handle {
       reverse_proxy {$SITE_HOST}:{$SITE_PORT}
     }
   }
   ```

   Переменные сервиса-прокси (Variables):
   - `CRM_HOST` = `имя-сервиса-crm.railway.internal`
   - `CRM_PORT` = порт, который слушает CRM (виден в настройках сервиса CRM)
   - `SITE_HOST` = `имя-сервиса-сайта.railway.internal`
   - `SITE_PORT` = порт сайта
3. **Домен.** Custom Domain `qural-saiman.kz` вешается **на прокси**, а не на
   CRM и не на сайт. Для корня домена — те же правила про CNAME flattening и
   Cloudflare, что в шаге 5 варианта А.
4. У сервиса CRM публичный домен Railway можно оставить как запасной вход.

Лимиты доменов в Railway: на тарифе Hobby — 2 своих домена на сервис, на
Pro — 20.

## Что прислать мне, когда решите

- какой вариант: А (поддомен) или Б (путь `/crm`);
- где будет сайт-визитка: казахстанский хостинг или Railway;
- у какого регистратора куплен домен — подскажу, где в его панели DNS.

Пароли и доступы к панелям присылать не нужно: все записи вносятся вами по
этой инструкции, от меня нужны только правки кода, если выберете вариант Б.
