# ПрокатCRM — статус проекта для передачи в новый чат

Это CRM для аренды строительного инструмента (Казахстан/Атырау, тенге), которую мы
строим итеративно в Claude. Ниже — всё, что нужно новому чату, чтобы понять контекст
и продолжить работу без потери истории решений.

**Как использовать этот файл:** загрузите его в начале нового чата вместе с ZIP-архивом
текущего проекта и напишите, что хотите сделать дальше. Claude прочитает этот файл и
поймёт, что уже сделано, какие есть ограничения и почему всё устроено именно так.

---

## 1. Что это и на чём написано

- Next.js 15 (App Router) + React 19 + TypeScript + Tailwind CSS 4
- **Реальный бэкенд**: SQLite через `better-sqlite3` (файл `data/app.db`), REST API
  через Next.js route handlers (`src/app/api/**`)
- Клиентское состояние — Zustand (`src/lib/store.ts`), но это только кэш поверх
  реального API, не источник истины (в отличие от самой первой версии, где
  использовался localStorage — это уже заменено)
- Дизайн: белый фон, тёмная левая панель (`#15121F`), фиолетовый акцент (`#6D4AFF`),
  карточки со скруглением 12–16px, мягкие тени — референс был на скриншотах Yume CRM,
  но не копия

## 2. Что уже полностью работает (проверено вживую через API и страницы)

### Клиенты (`/clients`)
Таблица, поиск/фильтры (тип, канал привлечения, рейтинг), сортировка по колонкам,
статистика (кол-во, % повторных, с просрочками, средний чек), импорт/экспорт CSV и
Excel (`src/lib/client-io.ts`, библиотека `xlsx`). Форма `/clients/new` и карточка
`/clients/[id]` — с реальным фото (загружается на диск), документом (ИИН, дата
рождения и т.д.), реальной историей аренд.

### Каталог инструмента (`/catalog`)
CRUD: список с фото/статусом/категорией, форма добавления/редактирования
(`/catalog/new`, `/catalog/[id]`), QR-код генерируется автоматически из артикула
(библиотека `qrcode`, компонент `src/components/inventory/qr-code.tsx`). При
оформлении аренды товар из каталога переходит в статус `rented`, при завершении/
отмене аренды — обратно в `available` (логика в `src/lib/repo.ts`,
функция `applyInventoryLock`).

### Аренды (`/rentals`, `/rentals/new`, `/rentals/[id]`)
- Список с фильтрами и счётчиками по статусам (Все/Запросы/Забронировано/В аренде/
  Просрочено/Должники/Отменённые/Архив)
- **Новая аренда** — полностью рабочая форма:
  - Поиск клиента по имени/телефону или создание нового прямо из формы
  - Даты начала/конца, пункт проката, период аренды, автоматический расчёт длительности
  - Добавление товара — два режима: «Из каталога» (выбор среди свободного
    инструмента, `src/components/rentals/add-catalog-item-modal.tsx`) и «Вручную»
    (для комплектов/услуг, которых в каталоге пока нет,
    `src/components/rentals/add-line-item-modal.tsx`)
  - Расчёт суммы с учётом скидки и штрафов, приём оплаты
  - Залог, штраф (с переключателем «Почасовой штраф» + ставка ₸/час), расходы, заметки
  - Кнопки «Сохранить изменения» (черновик, статус `request`) и «Забронировать
    аренду →» (статус `booked`, переход на карточку аренды)

### Автоматические штрафы за просрочку (реально протестировано)
Фоновый планировщик встроен в конец `src/lib/repo.ts` (не через `instrumentation.ts` —
см. раздел 6, «Грабли», почему). При первом обращении к любому API-роуту запускается
`setInterval` на час (первый прогон — через 10 секунд после старта процесса). Логика
в функции `applyOverdueAndPenalties()`:
- Аренды в статусе `active`/`booked`, у которых `end_at` в прошлом → статус `overdue`
- Если у аренды `auto_penalty_enabled=1` и задана `penalty_rate_per_hour` — за каждый
  полный час просрочки добавляется штраф в массив `penalties_json`, сумма `total`
  растёт автоматически
- Ручной запуск той же проверки: `GET /api/cron` (полезно, если процесс Node не
  работает постоянно — например, для внешнего cron/Task Scheduler на Windows)

Тест, который прогонялся и который прошёл: создал клиента и инструмент через API,
создал аренду с `endAt` на 3 часа в прошлом и `autoPenaltyEnabled: true,
penaltyRatePerHour: 500`, дёрнул `/api/cron` → статус стал `overdue`, добавилось
3 штрафа по 500₸, `total` вырос с 6000 до 7500.

### Реальные файлы
`POST /api/upload` — сохраняет файл на диск в `public/uploads/<timestamp>_<rand>.ext`
(до 8МБ, png/jpg/jpeg/webp/gif/pdf), возвращает URL, который отдаётся статически.
Используется в форме клиента и форме инструмента (`src/components/ui/photo-upload.tsx`).

## 5. Принципиальные решения, которые нельзя случайно откатить

- **Никаких фейковых/декоративных данных.** Раньше в проекте были случайно
  сгенерированные клиенты, аренды и выручка «для красоты» — заказчик явно попросил
  их убрать и оставить только то, что реально вводится пользователем. Дашборд и
  все счётчики стартуют с нуля. `mock-data.ts` содержит только статичные справочники,
  НЕ записи данных.
- **Источник истины — сервер (SQLite), не браузер.** Раньше был Zustand + persist в
  localStorage — это заменено на API + `store.hydrate()`. Если что-то не
  отображается, первым делом проверить, что `StoreHydrator` смонтирован в
  `src/app/layout.tsx` и что `hydrated`-флаг учитывается там, где раньше был риск
  ложного «Нет данных»/404 до завершения загрузки (`clients/[id]`, `rentals/[id]`,
  `clients/page.tsx`, `rentals/page.tsx`).

## 6. Грабли, на которые уже наступали (чтобы не наступать снова)

1. **Prisma не работает в песочнице разработки** — `npx prisma init` падает на
   `binaries.prisma.sh` (403, сеть блокирует). Поэтому выбран `better-sqlite3`
   (чистый npm-пакет). У пользователя на Windows сеть своя, но лучше не
   переключаться обратно на Prisma без причины — better-sqlite3 уже работает
   и протестирован.
2. **`src/instrumentation.ts` ломает сборку**, если внутри импортирует модуль,
   использующий `better-sqlite3` — Next.js бандлит instrumentation по особым
   правилам и не уважает `serverExternalPackages` для него. Решение: фоновый
   планировщик запущен НЕ через `instrumentation.ts` (файла больше нет в проекте),
   а как побочный эффект при импорте `src/lib/repo.ts`, с защитой через
   `global.__penaltySchedulerStarted`, чтобы не запускался повторно при hot-reload.
3. **`next.config.ts` обязательно должен содержать
   `serverExternalPackages: ["better-sqlite3"]`** — без этого дев-сервер отдаёт
   странную HTML-заглушку вместо API-ответов.
4. **В песочнице разработки фоновые процессы (`npm run dev &`) не переживают между
   отдельными вызовами bash-инструмента** — если в новом чате Claude будет
   тестировать сервер, всё (старт + `sleep` + все `curl`-проверки) нужно делать
   одной командой в одном вызове.
5. Next.js 15 App Router: `params` в динамических страницах и route handlers —
   это `Promise`, нужен `await params` (или `use(params)` в клиентских компонентах).

## 7. Должники и «Украдено» (последний шаг)

- **Должники** (`/rentals`, вкладка «Должники») теперь считаются только по-настоящему выданным арендам:
  статус `active` или `overdue` и `total > paid`. Раньше туда попадала любая неоплаченная запись, включая
  ещё не выданные брони — это исправлено (`status-tabs.tsx` и `app/rentals/page.tsx`).
- Новый статус аренды `stolen` («Украдено») и статус инвентаря `stolen` («Украден»).
- На карточке аренды (`rental-side-panel.tsx`), пока аренда в статусе `active`/`overdue`, доступна кнопка
  **«Украдено»** — с модалкой-подтверждением. При подтверждении одним действием:
  1. Все товары аренды получают статус инвентаря `stolen` (списываются из каталога, не возвращаются в `available`).
  2. Аренда переходит в статус `stolen`.
  3. Клиент автоматически помечается `blacklisted: true`.
- Раздел **«Чёрный список»** (`/blacklist`) больше не заглушка — реальный список клиентов с `blacklisted: true`,
  показывает количество краж по клиенту, позволяет вручную убрать из списка (`updateClient(id, { blacklisted: false })`).
- На карточке клиента (`/clients/[id]`) в шапке показывается бейдж «В чёрном списке», если применимо.
- Планировщик просрочек (`applyOverdueAndPenalties`) и авто-возврат инвентаря в `available` при завершении/отмене
  аренды не трогают статус `stolen` — оба места уже проверяют текущий статус перед перезаписью.

Что дальше может понадобиться (не сделано):
- Возврат товара, отмеченного украденным, вручную (если нашли инструмент) — сейчас статус меняется только
  вручную через форму каталога (`/catalog/[id]`), нет отдельной кнопки «Найден» на карточке аренды.
- Причина/комментарий при краже (сейчас фиксируется только сам факт, без свободного текста).
- Автопредупреждение при оформлении новой аренды, если выбранный клиент уже в чёрном списке (пока не блокирует
  и не предупреждает при создании аренды в `/rentals/new`).

## 8. Как запускать

```bash
npm install
npm run dev
```
Откроется на http://localhost:3000, база `data/app.db` создастся сама при первом
запросе к API. Ручная проверка штрафов: `GET http://localhost:3000/api/cron`.
